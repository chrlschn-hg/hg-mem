# Graph viewer libraries for the Paseo 0.12 plugin

Research finalized 2026-10-23. This comparison supports the isolated [graph viewer spike](../discovery/graph-viewer-spike/README.md); it does not select a production renderer or implement memory editing. Versions below identify the researched packages and the executed spike, not a promise of future compatibility.

## Result and limits

The lead reports successful **web mounting, pan/zoom, selection, resize, and cleanup for Sigma and Reagraph after browser prebundling**. The spike uses a synthetic 30-node, 49-edge graph. Direct imports failed at compilation because Graphology imports the Node builtin name `events`; the browser prebundle resolves browser dependencies before the Paseo compiler runs. Lazy loading alone did not fix compilation. See the [direct-import failure](../discovery/graph-viewer-spike/evidence/01-combined-install-failure.txt) and [install/runtime observations](../discovery/graph-viewer-spike/evidence/02-install-results.txt).

These results demonstrate the exercised web integration. They do not establish physical iOS/Android support, large-graph performance, accessibility, or compatibility with future Paseo releases. The RN primitives baseline was still being finalized when the lead requested this report; a web screenshot of that baseline is not a physical native test.

Sigma emitted repeated `GL_INVALID_OPERATION` messages while rendering and picking continued to work. Reagraph emitted Three/Troika deprecation/font messages. Their causes and wider consequences were not investigated; successful interactions do not resolve those observations. [Runtime evidence](../discovery/graph-viewer-spike/evidence/02-install-results.txt).

## Host compatibility is a separate requirement

Paseo 0.12 uses React **19.1.0** and React Native **0.81.5**. Its documented plugin host modules include React and React Native, but do **not** expose ReactDOM, SVG, Skia, or WebView as host module imports. The plugin reference explicitly disallows direct `react-native-svg` and DOM library imports for its cross-platform surface. The spike's browser adaptation is an empirical result, not a new documented cross-platform contract. [Plugin reference](https://paseo.sh/docs/plugins/reference), [tagged 0.12 app dependencies](https://github.com/getpaseo/paseo/blob/v0.12.0/packages/app/package.json).

The tagged app itself declares ReactDOM 19.1.0, Skia 2.2.12, SVG `^15.14.0`, and WebView `^13.16.0`. That does not establish plugin access or the modules available in any particular installed native binary. Installing a JavaScript dependency into a plugin does not supply a missing native host integration. Physical native operation remains **untested**.

Paseo's tagged compiler uses a neutral client target with `module`/`main` resolution, rather than browser-field resolution. React is externalized to the host; ReactDOM is not one of its externals. Therefore, lack of a host ReactDOM import does not prove a locally bundled browser renderer impossible. The completed prebundle probes provide the actual evidence here. [Paseo 0.12 compiler](https://github.com/getpaseo/paseo/blob/v0.12.0/packages/server/src/server/plugins/compiler.ts).

### Reagraph's React requirement needs the resolved tree

Reagraph 4.32.0 advertises top-level React/ReactDOM peers `>=16`, but its dependency on Fiber is `^9.6.1`. The actual spike lockfile resolves **Fiber 9.8.2** with React/ReactDOM peers `>=19 <19.4`, **Drei 10.7.9** with React/ReactDOM `^19`, and Three **0.184.0**. React/ReactDOM **19.1.0** satisfy those resolved peer ranges. The broad top-level range alone would be insufficient to establish compatibility. [Reagraph package metadata](https://registry.npmjs.org/reagraph/4.32.0), [executed variant lockfile](../discovery/graph-viewer-spike/variants/reagraph/package-lock.json).

The prebundle retains host React and `react/jsx-runtime` as externals while bundling the browser rendering dependencies. This avoids introducing a separate bundled React instance in that artifact. Version compatibility is a necessary check; module evaluation and actual mounting remain runtime gates. Fiber's optional native capabilities do not override Reagraph's explicit lack of RN support. [Executed prebundle configuration](../discovery/graph-viewer-spike/tools/prebundle-reagraph.mjs), [Reagraph installation guidance](https://reagraph.dev/docs/getting-started/Installing).

## Recommendations

1. **Keep Sigma 4 and Reagraph as the two demonstrated web candidates.** Prefer Sigma's imperative integration for a focused explorer; prefer Reagraph when its scene/layout features justify the dependency surface. Neither small successful probe establishes a performance winner. Resolve the observed Sigma GL errors before recommending that exact configuration for production.
2. **Keep a view built from exposed RN primitives as the cross-platform baseline.** Treat physical native operation as a separate gate. SVG, Skia and WebView require an explicitly supported host surface before becoming plugin options. Cytoscape is the most relevant unprobed web alternative if the two tested candidates hit a concrete blocker.
3. **Carry the probe's exact versions and integration path into any later decision.** Separate compile, module evaluation, mount, interaction, resize and cleanup evidence. If further evaluation is authorized, compare the same graph and fixed positions before comparing layouts; predeclare graph sizes and interaction/cleanup criteria. Do not infer native support or production scalability from the completed small web probe.

No additional experiments, installs, implementation, or environment changes were performed to finalize this comparison.
